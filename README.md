# Async Job Queue

[![CI](https://github.com/juanjosechiroque/async-job-queue/actions/workflows/ci.yml/badge.svg)](https://github.com/juanjosechiroque/async-job-queue/actions/workflows/ci.yml)

Go HTTP service that generates PDF files asynchronously. A request creates a job and returns immediately; the PDF can then be retrieved when its job has completed.

## Current status

Each accepted job runs in its own background goroutine. This version intentionally has no worker pool, queue, concurrency limit, database, or automatic file retention.

```text
POST /jobs -> validate -> create in-memory job -> generate and store PDF in background
```

`POST /job` is no longer available.

## Requirements

- Go 1.27, according to the version declared in `go.mod`.
- No external services or environment variables are required.

## Run the server

From the project root:

```bash
go run ./cmd/server
```

The public API server listens on `http://localhost:8080`; Go pprof is served separately and only on `http://127.0.0.1:6060/debug/pprof/`. The server creates `./storage` on startup. Press `Ctrl+C` to stop it. Shutdown stops new work, shuts down both HTTP servers, waits up to 30 seconds for active jobs, and then exits.

## API

### Create a PDF job

```http
POST /jobs
Content-Type: application/json

{"lines":100}
```

`lines` must be between `1` and `250000`. Each request creates a distinct job, including duplicate requests.

Successful response:

```http
202 Accepted
Content-Type: application/json
```

```json
{
  "jobId": "a8K2mP91xQ",
  "status": "queued",
  "downloadUrl": "/jobs/a8K2mP91xQ/file"
}
```

Job IDs are generated by the server with `crypto/rand`, are exactly 10 Base62 characters, and cannot be chosen by clients.

### Read job status

```http
GET /jobs/{jobId}
```

The response always includes `jobId` and `status`. Completed jobs also include `downloadUrl`; failed jobs include the safe error `job failed`.

Example completed response:

```json
{
  "jobId": "a8K2mP91xQ",
  "status": "completed",
  "downloadUrl": "/jobs/a8K2mP91xQ/file"
}
```

### Download a completed PDF

```http
GET /jobs/{jobId}/file
```

The endpoint returns `application/pdf` only for completed jobs. PDFs are stored privately under `./storage/{jobId}.pdf`; that directory is not exposed as a static route.

| Job state | HTTP | Result |
|---|---:|---|
| `queued` | `409` | `{"error":"job is queued"}` |
| `processing` | `409` | `{"error":"job is still being processed"}` |
| `completed` | `200` | PDF download |
| `failed` | `500` | `{"error":"job failed"}` |
| Unknown job ID | `404` | `{"error":"job not found"}` |

## Error responses

Errors use `application/json; charset=utf-8`.

| Situation | HTTP | Response |
|---|---:|---|
| Unsupported method on a known route | `405` | `{"error":"method not allowed"}` |
| Invalid request body | `400` | `{"error":"request body must be valid JSON"}` |
| `lines` outside the allowed range | `400` | `{"error":"lines must be between 1 and 250000"}` |
| Unknown job ID | `404` | `{"error":"job not found"}` |
| Service is shutting down | `503` | `{"error":"service is shutting down"}` |

Internal generation and storage details are not returned to clients.

## Try it with curl

Create a job:

```bash
curl -X POST http://localhost:8080/jobs \
  -H 'Content-Type: application/json' \
  -d '{"lines":10}'
```

Copy the returned `jobId`, then check it and download after its status is `completed`:

```bash
curl http://localhost:8080/jobs/a8K2mP91xQ
curl http://localhost:8080/jobs/a8K2mP91xQ/file -o result.pdf
```

## Storage and restart behavior

Job metadata and statuses exist only in process memory. Restarting the server loses all job records, including records for completed files. Existing files remain in `storage/`, but cannot be downloaded through the API after a restart because their metadata no longer exists.

Files are first written to a temporary file and atomically renamed when complete, so partial PDFs are never exposed by the download endpoint. Files and job metadata are retained indefinitely and must be cleaned manually. `storage/` is ignored by Git.

## Verification

Run from the project root:

```bash
make check
```

This formats the code, runs `go vet`, and runs the tests with the race detector.

CI runs the corresponding format check, vet, race-enabled tests with coverage, and build on every push to `main` and pull request targeting `main`.

## Current structure

```text
cmd/server/main.go        HTTP server startup, storage initialization, shutdown wiring
internal/jobs/handler.go  HTTP API handler
internal/jobs/model.go    Request, job state, and response models
internal/jobs/service.go  Validation, in-memory store, background job execution, file storage
internal/pdf/            PDF document generation
internal/text/           Per-line text selection
```
